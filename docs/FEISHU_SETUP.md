# 飞书任务通知

## 飞书后台准备

1. 在 https://open.feishu.cn/app 创建企业自建应用。
2. 添加机器人能力，开通 `im:message:send_as_bot`（以应用的身份发消息）。
3. 设置可用范围，包含需要接收通知的成员，创建版本并完成管理员审核发布。

本功能只主动发送通知，不读取飞书聊天记录，不需要配置事件回调、长连接或接收消息权限。

官方消息接口：https://open.feishu.cn/document/server-docs/im-v1/message/create

官方应用凭证接口：https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal

## 项目管理系统配置

1. 管理员打开“系统管理 → 飞书通知”。
2. 将“凭证与基础信息”中的 App ID 和 App Secret 填入配置表单，系统地址使用 `https://pm.jtgc.cc`。先保持自动通知关闭并保存。
3. 在人员绑定表中，为测试账号填写飞书 Open ID、用户ID或飞书通讯录登记邮箱，保存绑定。Open ID必须属于当前应用；请勿使用另一个应用的Open ID。
4. 点击该人员的“发送测试”，确认飞书中收到通知。
5. 完成其他人员绑定，扩大应用可用范围并发布后，勾选“启用自动通知”并保存。
6. 新增任务验证负责人和参与人员分别收到通知。负责人同时作为参与人员时仅发送一次。

填写邮箱不会修改系统账号或人员资料；此邮箱用于飞书识别用户，并不是发送电子邮件。不要仅凭姓名推断飞书身份。更换App ID需要重新填写App Secret，会解除旧绑定并取消待发送消息。

新增任务和任务变更分别有独立通知开关。变更通知发送给变更后的负责人和参与人员，不向已移出的人员发送任务内容。停用账号不接收通知。通知链接进入该项目的“里程碑与任务”，访问仍受系统登录和项目权限控制。

## 发送记录与重试

任务保存时，在同一个数据库事务中写入通知队列。网络发送在后台进行，飞书接口异常不会撤销任务保存。未绑定人员显示“未绑定”，补充绑定后可手动重试。

后台每5秒检查队列，失败自动退避重试，最多5次；失败记录可手动重试。关闭自动通知会暂停队列，重新开启后继续发送；测试发送不受自动通知开关限制，失败测试不会自动重发。服务重启恢复发送中的记录，使用原UUID去重。飞书UUID去重窗口有限，较长时间后手动重试或重启恢复可能重复送达，不承诺跨长时间窗口的恰好一次投递。

只有系统管理员能查看飞书配置、绑定、发送记录或触发测试/重试。界面显示最近100条记录，完整记录保留在数据库。

## 数据与密钥备份

新增 `pm_feishu_config`、`pm_feishu_bindings`、`pm_feishu_messages` 三个表及队列索引，全部是新增结构，不改写已有业务数据。默认自动通知关闭，不会为历史任务自动补发通知。

App Secret使用AES-256-GCM加密保存，密钥文件位于生产data目录的 `feishu-secret.key`，文件权限600。配置接口只返回“是否已保存”，不返回密钥或访问token；访问token仅在内存缓存。错误记录不保存飞书原始响应正文，避免回显敏感内容。

备份和恢复必须同时保留SQLite数据库、WAL/SHM、uploads及 `feishu-secret.key`。常规备份脚本已经增加密钥文件备份。部署脚本也必须在密钥存在时备份并校验它；没有密钥文件时，只能重新填写App Secret恢复发送能力，不能重建密钥后宣称旧配置可解密。

本地测试通过模拟飞书接口验证权限、密钥隐藏、事务回滚、去重、网络失败、重试、停用账号、绑定变更、服务重启恢复及手机布局。真实应用凭证和消息送达需在部署后由管理员配置并测试，未经配置不认为已经接通。
